# FYM V1 developer handoff

## Architecture

This is a static multipage site, not a Wix runtime or SPA. `npm run build` generates `dist/` using Node.js built-ins. It copies the approved pages/styles from `fym-site-copy/`, then injects content from `content/projects/*.json` and `content/team.json` into the existing design classes. `dist/` is deploy output and is ignored by Git.

Routes live as directory `index.html` files. The reusable project detail is generated by `projectMain()` in `scripts/build-site.cjs`; only active and completed projects receive detail routes. Coming-soon projects receive marketplace entries but no application CTA. The Home featured project comes from the one active JSON record with `featured: true`. The two historical client case studies live under `/our-work/` and are intentionally separate.

`src/`, `wix.config.json`, and the Wix embed script are legacy. They are excluded from the Netlify build and can be archived in a later cleanup after the replacement is accepted. The Google Form application URL is content in the active project JSON, not an environment secret. The FYM idea form is still an external Wix Form URL; migration of form responses is separate from site migration.

## CMS and deployment

`fym-site-copy/admin/config.yml` configures Decap's GitHub backend for `aayushjain1230/FYM-WEBSITE`, branch `main`. Decap saves project JSON, team JSON, and uploaded images back into this repository. The build copies uploaded images into `dist/assets/uploads/`.

The GitHub backend requires an OAuth provider. The Netlify site owner must register a GitHub OAuth app with callback `https://api.netlify.com/auth/done`, then configure the Client ID and Client Secret in **Netlify Project configuration > Security > OAuth**. Never commit them. Each editor needs repository write access. Test login, edit, commit, and redeploy with Olivia before launch. Git Gateway is deprecated for new configurations and is not used here.

`netlify.toml` publishes `dist/` after `npm run build`; it adds simple security headers and slash redirects. No environment variables are required for the public build. Connect the existing repo to a Netlify preview project. Do not cut over DNS or unpublish Wix until content, CMS login, forms, and mobile pages are approved.

## Local checks

```sh
npm ci
npm test
npm run dev
```

The test script checks output routes, application link safety, statuses, and obvious Wix-account placeholders. Review the rendered pages at desktop, tablet, and phone widths as well. Keep alt text on newly uploaded media and do not add unverified FYM claims.

## Future extension points

Members/accounts, application status, project teams, and idea-submission storage are Phase 2 and intentionally absent. The current application is a Google Form; there is no automatic association with a user account. Add any future system without changing the existing content model blindly.

FYM should control GitHub, Netlify, domain/DNS, Decap OAuth/access, Google Forms, and response Sheets, with at least two appropriate leaders holding admin access where possible.
